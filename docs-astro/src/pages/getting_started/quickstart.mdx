# Quickstart

You are on Pixano's home page, the Library, and it is empty. In the next few minutes you will
import a folder of your own photos from the app, open the result, then do the same import from
the command line. All you need is a folder holding 3 to 5 JPEG or PNG photos and nothing else —
no subfolders. We call it `my_photos` here. If you closed the server since
[Installation](/pixano/getting_started/installing_pixano/), start it again the same way.

## Import your photos from the app

### Open the wizard

<Figure src="getting_started/quickstart/01-library-empty.webp"
  alt="The empty Library: 'Your library is empty' with the Import dataset button."
  caption="The Library before your first import." />

1. Click **Import dataset**. The import wizard opens as a dialog.

### Type and Task

2. **What are you importing?** Click **Raw media** — a folder of images you will annotate from
   scratch. The steps listed across the top of the dialog — **Type**, **Task**, **Source**,
   **Review**, **Import** — are the headings that follow.
3. **What are you building?** Click **Image annotation**.

Each card takes you to the next step as soon as you click it.

### Source

4. Click **Choose a folder on your computer…** and select `my_photos`. A progress bar runs
   until the panel confirms the upload — **3 files** and their size — and a **Detected layout**
   panel shows what Pixano found: 3 records, one `image` view.
5. Leave **Dataset name (optional)** empty — the dataset takes the folder's name — and leave
   **If the dataset exists** on **Fail (create only)**. Under **Annotations**, the four
   pre-selected chips (`bbox`, `mask`, `keypoint`, `classification`) are the tools the workspace
   will offer; keep them.

<Figure src="getting_started/quickstart/02-wizard-source-detected-layout.webp" width={768}
  alt="The Source step after uploading the my_photos folder: 3 files uploaded and the Detected layout panel showing 3 records."
  caption="Everything on this step is optional except the folder." />

6. Click **Analyze**.

### Review

7. Pixano reads the folder without writing anything and shows the plan: **3 records**, the size
   of the media, the detected format (`PIXANO_JSONL`), a **Schema** panel listing the tables it
   will create — **Views**, **Record**, **Entity**, **Annotations** — and a few **Sample
   records**.

<Figure src="getting_started/quickstart/03-wizard-review-plan.webp" width={768}
  alt="Review the plan: 3 records, the schema Pixano will create, and three sample records."
  caption="Nothing has been created yet: this is the plan the import will execute." />

8. Click **Start import**.

### Import

9. The dataset is built on the server; for a handful of photos this takes a few seconds. (For
   large imports, **Run in background** lets you keep using the app meanwhile.) When the card
   reads **Dataset imported**, with a count per table, click **Done**.

You are back in the Library, and your dataset card is there.

<Figure src="getting_started/quickstart/04-library-dataset-card.webp"
  alt="The Library with the new my_photos card."
  caption="From now on, new imports start from the Import button in the toolbar." />

<Callout type="note" title="Other data, other choices">

The wizard's other cards import videos, Visual Q&A and image–text sources, or an existing
dataset — a Pixano export, MS COCO or LeRobot. `train/`, `val/` and `test/` subfolders become
splits; side-by-side folders such as `left/` and `right/` become views; **Record attributes**,
**Object attributes** and **Advanced spec (JSON)** shape the schema before analysis. Every
choice is described in
[Import from the app](/pixano/getting_started/importing_data/#import-from-the-app).

</Callout>

## Open your dataset

Click the card. The **Explorer** shows your records — one per photo — in a gallery; click any
record to open it in the annotation **Workspace**.

<Figure src="getting_started/quickstart/05-explorer-records.webp"
  alt="The Explorer showing the three imported records in the gallery."
  caption="Your first dataset, ready to annotate." />

Each photo became a **record**; the photo itself is the record's **view**; the objects you will
draw are **entities**, and every box or mask on them is an **annotation** — the four words you
saw in the Review step. [Key Concepts](/pixano/getting_started/key_concepts/) explains how they
fit together; [Using the App](/pixano/getting_started/using_the_app/) shows you around the
Explorer and the Workspace.

## Do the same from the command line

The wizard uploads your folder through the browser. When the photos already sit on the machine
that runs the server, or when you have many folders to import, the command line does the same
job without a browser. Leave the server running and open a second terminal in the same folder,
with the virtual environment activated. (With Docker, stay with the wizard: the commands below
assume a pip install.)

The wizard already created `my_photos`, and Pixano never overwrites a dataset on its own, so
this command gives the new one its own name — on an empty Library you could leave `--name` out:

```bash
pixano data import ./my_data ./my_photos --name my_photos_cli
```

Pixano analyzes the folder and prints its plan before writing anything:

```text
Format: pixano_jsonl (importer 1.0.0)
- Split 'default': 3 record(s)
Total: 3 record(s)
Schema (workspace: image):
- View 'image': Image
- Annotations: bbox, keypoint
Proceed with the import? [Y/n]:
```

No configuration file: the dataset takes the `image` workspace and the photos land in one split
called `default`. Press Enter; a progress bar runs, then:

```text
Dataset 'my_photos_cli' imported successfully (3 record(s), storage: embedded, job 97yWbnDErAxtCpXqP4Sy8L).
```

Refresh the Library in your browser: the new card is there. No restart is needed.

The two paths import the same photos, but not with the same annotation tables: the wizard's
image preset also created `mask` and `classification`, while the command line's default is
`bbox` and `keypoint`. To decide yourself, describe the dataset in a file.

### Describe the dataset in a dataset.yaml

Create `my_photos/dataset.yaml`:

```yaml
pixano: 2
format: pixano_jsonl
dataset:
  name: my_photos_detection
  workspace: image
schema:
  entity:
    attrs:
      category: str
  annotations: [bbox, mask]
```

`dataset` sets what the wizard's cards set: the name and the workspace. `schema` is what the
file is for: every object you annotate — every **entity** — gets a `category` text field, and
only bounding-box and mask tables are created. Run the import again, without `--name` this time
(the file provides it); the file is picked up because it sits at the root of the folder:

```bash
pixano data import ./my_data ./my_photos
```

The plan now ends with:

```text
- Entity attrs: category: str
- Annotations: bbox, mask
```

[Importing Data](/pixano/getting_started/importing_data/) documents every key of this file, and
how to bring existing annotations, COCO or LeRobot data along.
[Key Concepts](/pixano/getting_started/key_concepts/) explains the schema it describes.
