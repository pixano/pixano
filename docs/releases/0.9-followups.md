# 0.9 follow-ups

Accepted follow-ups from the 0.8 release review. These are development targets,
not capabilities promised by 0.8.

| Area                      | Current 0.8 behavior                                                                                                                                              | Follow-up                                                                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| LeRobot JSONL export      | Time-series data are omitted and exported annotation schemas can be incomplete; JSONL is not a LeRobot backup format.                                             | Preserve schemas, time-series, and annotations through export/re-import, with representative LeRobot round-trip coverage.        |
| Import tray after refresh | The browser keeps tracked jobs in memory. Refresh clears the tray while backend jobs continue.                                                                    | Restore active/recent jobs from the durable job store and resume progress, cancellation, and completion refresh.                 |
| Abandoned uploads         | Completed or cancelled imports clean up their sources; old orphaned uploads are collected at startup. A continuously running server can retain abandoned uploads. | Add periodic cleanup that protects active uploads and sources needed by resumable jobs.                                          |
| Review-plan expiry        | Saved plans expire after 24 hours. Starting an expired plan requires analysis again; interrupted jobs using it cannot resume.                                     | Retain immutable execution plans for resumable jobs independently of review expiry; provide re-analysis for expired setup plans. |
| Inference connections     | Connected providers live in memory and must be connected again after a backend restart.                                                                           | Persist and restore suitable connection configuration with explicit credential handling.                                         |
| Semantic search           | Text queries and similar-record search rank image records; computation stores one image embedding per record.                                                     | Add text-record embedding support. Per-view embeddings came with the embeddings job (below).                                     |
| 3D annotation             | 3D boxes, keypoints, and camera calibration are outside the 0.8 scope.                                                                                            | Continue the separate 3D data-model and workspace workstream.                                                                    |

AV1 browser playback and local-storage-only import/export jobs remain documented
constraints. Transcoding and object-store-safe job execution need separate scope
decisions; this list does not commit them to 0.9.

## Known limitations of 0.9

To carry into the 0.9 release notes (`docs/releases/0.9.0.md`).

- **Background jobs need a worker from the repository.** `pixano-worker` has no
  published package or image, so `pip install pixano` and the `pixano/pixano`
  image run no processing job: no embeddings job.
  Jobs need the repository's compose stack (`docker compose up`), or a worker
  installed from a checkout ([running the stack by hand](../running-by-hand.md)).
  Whether the worker is released together with Pixano is still to be decided
  (`RELEASING.md`, Transition).
- **Without a worker, embeddings are one per record.** The legacy explorer's
  own embeddings computation embeds one image per record, and the explorer
  counts embedded images: on a dataset with several images per record, it stays
  partial whatever is recomputed. Embedding every image takes the embeddings
  job, so a job queue and a worker from the repository (above). Vectors already
  written one per record stay beside the per-image ones a worker's job writes.
- **A model's output on video cannot be reviewed yet.** The boxes and masks the
  legacy video tools store — SAM2 video tracking, tracking by detection — are a
  model's output, and stay `pending` unless a person edits one in the legacy
  workspace, which stores it accepted. Gluing two tracks, fusing objects or
  relinking a track to another object there saves every frame's row it moves,
  and so accepts each of them, though nobody looked at it frame by frame. The
  new UI has no video view and the legacy app reviews still images only, so
  the next record to review (`GET /datasets/{id}/review/next`) is never one of
  theirs, and an export of accepted annotations (`--review-status accepted`)
  leaves out those still pending.
