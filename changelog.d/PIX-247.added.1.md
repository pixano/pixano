An import can queue the statistics job of a dataset's default statistics — how many objects,
boxes and masks each record holds, the share of its image each object's boxes cover — once it is
done: `compute_statistics` in `POST /io/imports`, `--statistics`/`--no-statistics` on
`pixano data import`, and by default wherever a worker declared the job, unless
`PIXANO_STATISTICS_AFTER_IMPORT` is false. The job computes the default statistics whose table
holds rows, keeping the label a person gave them, every one again after an add import; a dataset
with nothing to count needs none, which the import tells as not needed (`skipped` in a job's
`follow_ups`). Once the job has run, as once the embeddings job has, the rollback of an add import
is refused: pass `compute_statistics: false` or `--no-statistics` too to keep the rollback. The job
queue is now asked once for every follow-up of an import, and a follow-up that cannot be prepared
no longer keeps the others from being queued.
